## 2. 面试开场陈述

### 2.1 30 秒版本

> MyMusic 是我使用 ArkTS 和 ArkUI 开发的 HarmonyOS 音乐客户端。项目重点不是静态页面，而是完整播放器工程：我封装了网络请求、AVPlayer 和 AVSession，处理了在线歌曲地址按需解析、后台播放、系统播控、播放模式、收藏持久化和离线兜底。针对快速连续点歌可能出现的异步竞态，我使用递增操作序号淘汰过期请求，并把队列、随机和收藏策略提取成纯逻辑，当前有 32 个单元测试以及一套设备验收清单。

### 2.2 两分钟版本必须覆盖

- 为什么选这个项目：用真实媒体场景学习 HarmonyOS 应用开发和系统能力。
- 核心技术：ArkTS、ArkUI、AVPlayer、AVSession、Preferences、HTTP。
- 最大难点：异步切歌竞态、在线地址失效、播放器与页面状态同步。
- 解决方法：双层操作序号、按需地址解析、共享响应式状态、统一 Manager。
- 工程质量：分层、错误兜底、资源释放、纯逻辑测试和设备验收。
- 当前边界：依赖本地音乐接口，AI 功能关闭，尚未做正式后端和版权体系。

完成标准：不看文档，能够自然讲完，并控制在两分钟以内。

## 3. 架构必须能画出来

```text
Page
  Recommend / Find / Play / Mine / Layout
       ↓ 用户事件与界面状态
ViewModel
  FindViewModel / PlayViewModel
       ↓ 业务编排
Service / Repository / Policy
  MusicService / MusicSettingsRepository
  SongPlaybackResolver / PlaybackQueuePolicy / FavoriteSongsPolicy
       ↓ 平台资源
Manager / HarmonyOS API
  AvPlayerManager → AVPlayer
  AvSessionManager → AVSession + 后台长时任务
```

必须能解释：

- Page 不直接拥有第二个播放器，只负责展示与转发操作。
- ViewModel 管理页面状态和业务意图，不直接处理系统资源生命周期。
- Service 负责外部数据，Repository 负责本地持久化。
- Policy 和 Resolver 尽量保持纯逻辑，便于脱离设备测试。
- Manager 是 AVPlayer、AVSession 等系统对象的唯一管理入口。

## 12. 必须会回答的项目追问

### 12.1 为什么不用一个页面写完所有逻辑？

回答要点：页面、业务编排、数据访问和系统资源生命周期变化频率不同；分层后可以减少耦合，并让队列、收藏和解析策略脱离设备测试。

### 12.2 这个项目最难的 Bug 是什么？

回答要点：异步切歌竞态。旧请求晚返回会覆盖最新歌曲，导致页面信息与实际声音不一致。通过页面意图序号和播放器操作序号，在每个异步边界后淘汰过期操作。

### 12.3 为什么有两个序号？

回答要点：页面序号只覆盖发现页请求，播放器序号覆盖播放列表、系统播控、迷你播放器等全部入口，是最终一致性保护。

### 12.4 为什么不一次获取整张歌单所有 URL？

回答要点：请求数量大、首屏变慢，而且 URL 可能过期；按需解析能减少请求并获得更新的地址。

### 12.5 为什么收藏里不直接永久保存 URL？

回答要点：收藏保存的是歌曲身份和展示信息，在线 URL 属于短期资源；重新播放时按 ID 获取最新地址更可靠。

### 12.6 AVPlayer 和 AVSession 有什么区别？

回答要点：AVPlayer 管音频播放和进度，AVSession 把元数据、状态和控制能力暴露给系统媒体中心，两者需要同步但职责不同。

### 12.7 为什么使用 AppStorageV2？

回答要点：播放页、列表、收藏页和迷你播放器都需要观察同一份状态；共享响应式对象避免手动逐页通知和状态副本不一致。

### 12.8 为什么还需要 Preferences？

回答要点：AppStorageV2 解决运行期共享，进程结束后会丢失；播放模式和收藏需要跨启动恢复，所以另外持久化。

### 12.9 网络失败时用户会看到什么？

回答要点：无旧列表时进入离线曲库，有旧列表时保留当前内容；均显示明确提示和重试入口，不白屏、不清空用户上下文。

### 12.10 如果继续产品化，你会怎么改？

回答要点：自建合规后端、账户与云同步、数据库保存历史数据、正式签名与隐私合规、实体多设备测试、监控与性能指标；不会把第三方接口和 AI 密钥直接放进客户端。

## 13. 不能夸大的地方

- 动态页是展示性内容，不应描述成真实社交系统。
- AI 推荐默认关闭，因为没有安全的服务端代理。
- 在线音乐依赖本地接口，不能描述成正式商业音乐服务。
- 当前主要在 phone 模拟器验收，不能宣称已完成全设备适配。
- HAP 是未签名调试构建，不是应用市场发布版本。
- 32 个单元测试覆盖的是关键纯逻辑，不代表整体覆盖率达到生产级。

坦诚边界不会减分；能够说明下一步如何解决，通常比包装不存在的功能更有说服力。
